# 瞬截 / SwiftSnip 设计规格

> 状态：已获用户批准（2026-09-11）

## 1. 目标

为 Windows 10 提供一个轻量、高性能的截图工具：常驻托盘，通过全局快捷键触发，
支持鼠标拖拽选择区域截图与全屏截图，截图结果自动保存为 PNG 文件。

## 2. 命名

- 中文名：瞬截
- 英文工程名：SwiftSnip
- 项目目录：`D:\project\SwiftSnip`

## 3. 技术选型

- 语言：C++17（MSVC 14.44）
- 界面：纯 Win32 API（无 MFC / Qt / 第三方库）
- 图形：GDI 位块传输（捕获、遮罩渲染），WIC 编码 PNG
- 构建：`build.bat` 调用 vcvars64 + cl，Release `/O2 /MT` 静态链接
- 运行环境：Windows 10 1607 及以上（PerMonitorV2 DPI 感知）

选型依据：本机已安装 VS BuildTools 2022（MSVC 14.44）与 Windows SDK 10.0.26100，
无需新增任何工具链；原生实现可达成"单文件 < 1 MB、常驻内存 < 15 MB"的目标。

## 4. 功能范围（v1）

做：

1. 常驻托盘、单实例运行、无主窗口
2. 全局快捷键（可自定义）：区域截图、全屏截图
3. 区域截图：冻结屏幕遮罩 + 鼠标拖拽 + 实时尺寸提示 + 选区移动/缩放 + Enter 确认 / Esc 或右键取消
4. 全屏截图：可选主显示器或全部显示器
5. 截图结果自动保存 PNG（不写剪贴板），托盘气泡提示保存结果
6. 设置窗口：热键录制、保存目录选择、全屏范围、开机自启、打开保存目录

不做（列入 v2 候选）：标注编辑、滚动长截图、录屏/GIF、OCR、云分享、剪贴板写入、截取鼠标光标。

## 5. 已确认的决策

| 决策点 | 结论 |
| --- | --- |
| 软件名 | 瞬截 / SwiftSnip |
| 技术路线 | C++ Win32 |
| v1 标注功能 | 不做，v1 稳定后再评估 |
| 区域截图默认热键 | Ctrl+Alt+A |
| 全屏截图默认热键 | Ctrl+Alt+F |
| 截图结果 | 仅自动保存 PNG，不复制到剪贴板 |

## 6. 架构

```
src/
  main.cpp          入口、单实例、消息循环、热键分发、保存流程编排
  app.h             全局常量与自定义消息
  dpi.cpp/.h        DPI 感知初始化
  settings.cpp/.h   INI 配置读写、热键字符串转换、默认路径
  hotkey.cpp/.h     全局热键注册/注销/冲突检测
  tray.cpp/.h       托盘图标、右键菜单、气泡提示
  capture.cpp/.h    虚拟屏幕/主显示器捕获、裁剪、变暗副本
  png_writer.cpp/.h WIC 编码 PNG 落盘
  overlay.cpp/.h    区域选择遮罩窗口（拖拽、手柄、确认/取消）
  settings_win.cpp/.h 设置窗口（热键录制、目录选择、开关项）
  autostart.cpp/.h  开机自启（HKCU Run）
```

数据流：热键 → `capture` 抓取虚拟屏幕位图 → `overlay` 显示遮罩并收集选区
→ `capture::CaptureRect` 裁剪 → `png_writer` 保存 → `tray` 气泡提示 → 释放位图。

### 关键实现约束

- 进程声明 `DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2`，全流程使用物理像素，
  遮罩窗口客户区坐标与位图坐标一一对应。
- 遮罩窗口覆盖整个虚拟屏幕（含负坐标多显示器），底图为预生成的变暗副本，
  拖动时按无效区域局部重绘并双缓冲，避免闪烁与全屏重传。
- 热键注册失败（被占用）时给出气泡提示并引导用户到设置窗口修改，不静默失败。

## 7. 配置

配置文件：`%APPDATA%\SwiftSnip\config.ini`

| 键 | 说明 | 默认值 |
| --- | --- | --- |
| `HotkeyRegion` | 区域截图热键 | `Ctrl+Alt+A` |
| `HotkeyFullscreen` | 全屏截图热键 | `Ctrl+Alt+F` |
| `SaveDir` | 保存目录 | `<exe目录>\Pictures` |
| `FullscreenScope` | 全屏范围（0 主屏 / 1 所有屏幕） | 0 |
| `AutoStart` | 开机自启 | 0 |

文件命名：`SwiftSnip_yyyyMMdd_HHmmss.png`，同秒重名自动追加序号。

## 8. 错误处理

| 场景 | 行为 |
| --- | --- |
| 热键被占用 | 气泡提示"热键已被占用，请在设置中修改"，软件继续运行 |
| 创建保存目录失败 | 气泡提示具体错误，不生成文件 |
| PNG 编码/写入失败 | 气泡提示失败原因 |
| 屏幕捕获失败 | 气泡提示"截屏失败"，不弹遮罩 |
| 选区小于 3×3 像素 | 视为误触，不产生文件 |
| 受保护内容（DRM/独占全屏） | 系统限制，提示可能为黑屏 |

## 10. 验收标准

1. 托盘图标常驻，左键单击触发区域截图，右键菜单含全屏截图/设置/打开保存目录/退出
2. `Ctrl+Alt+A` 唤起遮罩，可拖拽选区、移动、缩放，Enter 确认，Esc/右键取消
3. `Ctrl+Alt+F` 按设置范围直接完成全屏截图并保存
4. 截图保存为 PNG，可在设置中修改保存目录，重启后配置保持
5. 热键可重新录制，冲突时有明确提示
6. 100%/125%/150%/200% 缩放与多显示器场景下选区与输出图像一致
7. 关闭软件后托盘图标消失，无残留进程；重复启动不产生第二个实例

## 11. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 多显示器混合 DPI 坐标错位 | PerMonitorV2 + 物理像素全程换算；若单窗口遮罩在混合 DPI 下异常，overlay 内部改为每显示器独立遮罩（对外接口不变） |
| 快捷键被占用 | 注册失败即提示并提供设置入口 |
| DRM/独占全屏截黑 | 系统限制，文档标注为已知限制 |
| 默认保存目录位于只读位置 | 保存失败时提示，可在设置中改为任意可写目录 |

## 13. 长截图（2026-09-11 追加，已获用户批准）

### 13.1 交互流程

1. 按 `Ctrl+Alt+S`（可自定义）或托盘菜单"长截图"
2. 屏幕冻结，拖拽选择要滚动的内容区域（复用现有遮罩，支持移动/缩放）
3. `Enter` 开始自动滚动捕获，程序循环执行：移动光标到选区中心 → 发送滚轮 → 截帧 →
   与上一帧做图像匹配求真实位移 → 拼接新增条带
4. 结束条件（任一满足）：连续两次检测到画面不再变化（已到底）／累计高度达到上限
   20000 像素／用户按 `Esc` 或再次按热键
5. 保存为 `SwiftSnip_Long_yyyyMMdd_HHmmss.png`，与普通截图同一目录

### 13.2 关键技术决策

| 决策点 | 结论 |
| --- | --- |
| 自动滚动实现 | `SendInput` 模拟真实滚轮（方案 A）：兼容性最好，代价是滚动期间光标被移到选区中心，结束后恢复原位 |
| 拼接实现 | 图像模板匹配（方案 A）：每帧在上一帧中搜索匹配位置得到真实位移，任意滚动量都能无缝拼接 |
| 拼接算法 | 取当前帧顶部最多 64 行为模板，在上一帧中以 SAD（采样列/行）搜索最小差异位置；阈值 32 判定可信度 |
| 自适应步长 | 先滚动 1 格测量实际位移，再按"选区高度 × 65%"换算每次滚动的格数（1–10 格），保证相邻帧约 35% 重叠 |
| 结束判定 | 连续 2 次匹配位移为 0 或匹配分数超阈值视为到底 |
| 内存策略 | `CreateDIBSection` 动态扩容长图缓冲（1.5 倍增长），每帧只拷贝新增条带；上限 20000 像素 |
| 停止方式 | 低级键盘钩子捕获 `Esc`（并吞掉该键），或再次按长截图热键 |
| 提示方式 | 不显示任何覆盖窗口（避免被拍进长图），仅用托盘气泡提示开始与结果 |

### 13.3 涉及模块

- 新增 `src/scroll_capture.cpp/.h`：滚动会话状态机（定时器驱动）、模板匹配、拼接、键盘钩子
- `overlay` 增加"只取选区"模式（`cropImage=false`），回调携带 `RegionSelection{bitmapRect, screenRect}`
- `settings`/`hotkey`/`tray`/`settings_win` 增加第三个热键项（默认 `Ctrl+Alt+S`）
- `main` 负责编排：遮罩取选区 → 启动滚动会话 → 保存长图（文件名加 `_Long` 标识）

### 13.4 实测结果（2026-09-11）

| 项 | 结果 |
| --- | --- |
| 长截图端到端 | PASS：3000 像素测试内容（随机纹理 + 29 条标识带）输出 700×2900，标识带顺序零违规 |
| 手动停止 | PASS：滚动 1.6 秒后按热键停止，保存 700×1150 部分长图 |

### 13.5 已知限制

- 只支持向下滚动；固定表头/浮动元素不会重复截入（其位置在每帧中不变，只保留第一帧内容）
- 光标位置必须落在目标应用的滚动区域内，且目标应用需响应滚轮消息
- 大面积均匀色块内容缺少匹配特征，可能导致拼接偏移；真实网页/文档/代码等内容不受影响

### 13.6 修复记录（2026-09-11 用户反馈：长图只截到一屏）

**问题现象**：对真实网页（深色主题 + 顶部固定导航栏 + 内容稀疏）做长截图，
输出长图仅比一屏高 43 像素，未包含后续滚动内容。

**根因分析**（通过临时日志与逐帧数据定位）：

1. 滚动阶段的位移搜索范围是"期望位移的 0.85~1.15 倍"，**不包含 0**。
   页面滚动到底后画面不再变化，但匹配无法返回"零位移"，
   只能在范围边界附近找到假匹配（实测：同位置帧差为 0.00 的静止帧被报出 213 像素位移）。
2. 顶部固定导航栏导致以顶部条带为模板的匹配在静态区域"锁定"。
3. 深色低对比内容中大面积为纯色，单条带匹配的区分度不足，容易接受错误位置。
4. 底部候选条带在大位移时会超出上一帧范围（内容尚不可见），产生假匹配。

**修复内容**：

| 修复 | 说明 |
| --- | --- |
| 静止检测 | 每次比对"同位置帧差"，低于阈值（0.5）直接判定画面未变化，不再进入匹配 |
| 搜索范围包含 0 | 滚动阶段位移搜索范围改为 `[0, 期望位移×1.15]`，静止时能正确返回零位移 |
| 多候选条带 + 多数表决 | 在选区内取 4 个位置的条带分别匹配，固定表头/浮动元素给出少数派结果被淘汰 |
| 候选位置自适应 | 模板位置限制在"模板+最大位移仍落在上一帧内"的可行区间，避免不可见区域的假匹配 |
| 两阶段搜索 | 粗搜（稀疏采样 + 4 像素步进）定位后，在附近 ±8 像素精搜，兼顾速度与精度 |
| 唯一性检查 | 精搜中最佳与次佳分数差小于 0.5 视为内容重复、结果不可信 |
| 阈值收紧 | 匹配分数上限从 32 收紧到 12，减少低对比内容的假匹配被接受 |
| 步长调整 | 单次滚动量从选区高度的 65% 降到 45%，保证相邻帧重叠更充分 |

**验证**：新增 `tests/e2e_scroll_sticky_header.py`（固定导航栏 + 深色低对比内容 + 3000 像素滚动区），
修复前只能截到一屏（或无限拼接），修复后输出 700×3100 的完整长图，29 个渐变色标顺序零违规。

### 13.7 修复记录（2026-09-11 用户反馈：提示被拍进长图）

**问题现象**：长截图右侧出现一列重复的"长截图进行中"提示文字，画面显得异常。

**根因**：滚动开始时弹出的托盘气泡固定在屏幕右下角，长截图每帧都会捕获到它；
由于气泡位置固定而页面内容滚动，气泡被逐帧拼接进长图并重复出现（用户系统上的通知显示时长较长）。

**修复**：

| 修改 | 说明 |
| --- | --- |
| 移除滚动期间的托盘气泡 | 长截图过程中不再调用气泡提示，避免任何屏幕元素被逐帧捕获 |
| 新增选区外框 | 在选区外侧 4 像素绘制蓝色细边框（点击穿透、不夺焦点），表示"进行中"与滚动范围；边框完全位于选区之外，不会被截入 |
| 遮罩提示文案 | 长截图模式下遮罩提示改为"拖动选择滚动区域 · Enter 开始长截图 · 开始后按 Esc 或再按热键结束"，操作说明在开始前给出 |
| 结果提示保留 | 仅在捕获结束保存完成后显示气泡，此时不会再影响图像 |

**验证**：长图宽度精确等于选区宽度（700 像素），确认选区外的边框未被截入；
固定表头场景（700×3100）与普通长截图（700×2900）回归全部通过。
